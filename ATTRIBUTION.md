# Attribution and provenance

The prose, numerical utilities, notebooks, original engine inputs and figures were prepared as original educational material for this course. Scientific ideas remain credited to their original sources in [references](references.md). The course was prepared with AI assistance; execution and review limits are stated in [VALIDATION_REPORT](VALIDATION_REPORT.md). Scientific contributions and corrections are welcome.

## Bundled third-party scientific assets

RASPA3's MFI structure, methane model and force-field example originate from the public MIT-licensed project maintained by its named authors. The exact source commit, file URLs and upstream checksums are in [THIRD_PARTY_PROVENANCE.json](data/THIRD_PARTY_PROVENANCE.json), with the complete [license notice](licenses/RASPA3-MIT.txt).

The original simulation JSON and Python driver are retained with `upstream_` filenames for comparison. The course's pilot JSON changes cycle lengths/output choices and makes its local force-field use explicit. The force-field teaching copy corrects the silicon element and display labels from Al to Si; numeric LJ parameters are unchanged, and the teaching cutoff is explicitly set to 12 Å. The provenance distinguishes source and modified hashes. These corrections are not presented as a new parameterization.

## Runtime dependencies

NumPy, SciPy, Matplotlib, Jupyter tools, ASE and OpenMM retain their own licenses. No installed package, executable or pretrained ML weight is bundled. OpenMM-generated system parameters are reproducible from the named force-field XMLs in the installed OpenMM distribution. Serialized parameter files are excluded from this archive. Consult their individual source headers and license notices when redistributing derived parameter sets.

## Linked teaching resources

[Source review](SOURCE_REVIEW.md) credits the LAMMPS, GROMACS, OpenMM, ASE, CP2K, RASPA3, FEASST, PLUMED, MDAnalysis and i-PI resources inspected. No textbook chapters, external diagrams or large tutorial passages are copied. Numerical validation data are generated by the supplied original algorithms or explicitly named engine models.
